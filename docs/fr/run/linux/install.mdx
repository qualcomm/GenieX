Le parcours Linux Docker s'appuie sur une image conteneur conçue pour Linux ARM64 avec accès au NPU (Dragonwing QCS9075 et plateformes IoT similaires).

<Note>
  Il s'agit du parcours conteneurisé. Si vous préférez installer `geniex` directement sur l'hôte sans Docker, consultez [Installation de la CLI → Linux ARM64 (Natif)](/fr/run/cli/install).
</Note>

### **Prérequis**

- Hôte Linux ARM64 avec Docker installé. Si vous n'avez pas encore Docker, suivez le [guide d'installation Docker pour Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
- Chipset IoT Dragonwing. Voir [Plateformes prises en charge](/fr/get-started/platforms).

<a id="install-host-dependencies"></a>
<a id="installer-les-dependances-hotes"></a>
### **Installer les dépendances hôtes**

Le conteneur accède au NPU via les bibliothèques de pilotes Qualcomm de l'hôte, montées via `-v /usr/lib:/opt/qcom-lib:ro`. Installez-les **sur l'hôte** avant `docker run` - suivez [Installation de la CLI → Installer les dépendances hôtes](/fr/run/cli/install#install-host-dependencies).

### **Télécharger l'image (pull)**

L'image est hébergée sur Docker Hub (publique, sans authentification requise) :

```bash bash
IMAGE=docker.io/qualcomm/geniex:latest

docker pull "$IMAGE"
```

<Note>
  Si `docker pull` renvoie `permission denied ... /var/run/docker.sock`, consultez [Dépannage → Linux](/fr/resources/troubleshooting#linux) pour la configuration du groupe `docker`.
</Note>

<Note>
  **Cartes de référence ARMv8.0**. Certains SoC Dragonwing IoT sans NPU ne peuvent pas exécuter l'image par défaut en ARMv8.2 ; ajoutez `-cpu` au tag pour ces systèmes : `docker.io/qualcomm/geniex:latest-cpu`. Cette image est purement CPU et ne nécessite ni `--privileged` ni le montage de `/usr/lib` ci-dessous.
</Note>

<a id="run-interactively"></a>
<a id="executer-en-mode-interactif"></a>
### **Exécuter en mode interactif**

Ouvrez un terminal interactif à l'intérieur du conteneur :

```bash bash
docker run -it --rm --privileged \
  -v "$PWD/data:/data" \
  -v /usr/lib:/opt/qcom-lib:ro \
  "$IMAGE"
```

### **Vérification**

Exécutez ensuite une commande de test dans le shell du conteneur :

```bash bash
geniex --help
```

<Note>L'option `--privileged` est obligatoire pour l'accès au NPU.</Note>

Pour le mode serveur, consultez [Serveur local](/fr/run/cli/local-server).
