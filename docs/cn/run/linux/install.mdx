Linux Docker 路径通过 Linux ARM64 容器镜像运行，并支持 NPU 访问（适用于跃龙 QCS9075 等 IoT 平台）。

<Note>
  这是容器化路径。若你更希望在宿主机上直接安装 `geniex` 而不使用 Docker，请参见 [CLI 安装 → Linux ARM64 (Native)](/cn/run/cli/install)。
</Note>

### **前置条件**

- 安装了 Docker 的 Linux ARM64 主机——若尚未安装 Docker，请参照 [Docker 的 Ubuntu 安装指南](https://docs.docker.com/engine/install/ubuntu/)。
- 跃龙 IoT 芯片——详见[支持的平台](/cn/get-started/platforms)。

### **安装宿主机依赖**

容器通过 `-v /usr/lib:/opt/qcom-lib:ro` 挂载的宿主机高通驱动库来访问 NPU。请在执行 `docker run` **之前**，在**宿主机**上安装这些库——参见 [CLI 安装 → 安装宿主机依赖](/cn/run/cli/install#安装宿主机依赖)。

### **拉取镜像**

镜像发布在 Docker Hub（公开，无需登录）：

```bash bash
IMAGE=docker.io/qualcomm/geniex:latest

docker pull "$IMAGE"
```

<Note>
  若 `docker pull` 返回 `permission denied ... /var/run/docker.sock`，参见[故障排查 → Linux](/cn/resources/troubleshooting#linux) 了解 `docker` 组的修复方法。
</Note>

<Note>
  **基线 ARMv8.0 板子** —— 部分无 NPU 的 Dragonwing IoT SoC 跑不了默认的 ARMv8.2 镜像，这类板子请在 tag 后加上 `-cpu`：`docker.io/qualcomm/geniex:latest-cpu`。该镜像仅支持 CPU 推理，既不需要 `--privileged`，也不需要下面的 `/usr/lib` 挂载。
</Note>

### **交互式运行**

进入容器内交互式 shell：

```bash bash
docker run -it --rm --privileged \
  -v "$PWD/data:/data" \
  -v /usr/lib:/opt/qcom-lib:ro \
  "$IMAGE"
```

### **验证**

然后在容器 shell 中运行测试命令：

```bash bash
geniex --help
```

<Note>NPU 访问需要 `--privileged` 标志。</Note>

服务器模式参见[本地服务器](/cn/run/cli/local-server)。

## **非骁龙 ARM64 主机**

若要在没有骁龙芯片的 ARM64 机器上试用 GenieX CLI（例如运行 Docker Desktop 的 Apple Silicon Mac），请使用 [`.github/docker/cpu-host.Dockerfile`](https://github.com/qualcomm/GenieX/blob/main/.github/docker/cpu-host.Dockerfile) 构建仅 CPU 镜像。该镜像基于 `docker.io/qualcomm/geniex:latest-cpu`，既不需要 `--privileged`，也不需要 `/usr/lib` 挂载；首次启动时会自动设置芯片，因此 `geniex pull` 不会提示选择芯片，`geniex infer` 也会默认使用 `--compute cpu`。

<Warning>
  此路径仅用于开发和测试。它只在 CPU 上运行，因此速度不代表骁龙平台的性能。请在 `llama_cpp` 运行环境上使用 GGUF 模型：Qualcomm AI Hub 模型包需要 NPU。
</Warning>

该镜像未发布到 Docker Hub，请从本仓库的克隆构建：

```bash bash
git clone --depth 1 https://github.com/qualcomm/GenieX.git
cd GenieX
docker build -f .github/docker/cpu-host.Dockerfile -t geniex-cpu-host .
```

启动容器，并将模型保存在 `./data` 中：

```bash bash
docker run -it --rm -v "$PWD/data:/data" geniex-cpu-host
```

然后在容器 shell 中拉取并运行模型：

```bash bash
geniex pull unsloth/Qwen3-VL-2B-Instruct-GGUF:Q4_0 --model-type vlm
geniex infer unsloth/Qwen3-VL-2B-Instruct-GGUF:Q4_0 -p "Describe this image: /data/image.jpg"
```

图片路径必须是容器内的绝对路径，因此请将图片放在宿主机的 `./data` 目录中。

<Note>
  已在 Apple M1 Max、Docker Desktop 和 GenieX CLI v0.10.0 上测试。`--compute cpu` 默认值来自该镜像设置的 `qualcomm-qcs6490` 芯片。如果将 `GENIEX_CHIPSET` 设为其他芯片，或 `/data` 中已配置其他芯片（已有配置不会被更改），请为 `geniex infer` 传入 `--compute cpu`。
</Note>
