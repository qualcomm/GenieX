The Linux Docker path runs through a container image built for Linux ARM64 with NPU access (Dragonwing QCS9075 and similar IoT platforms).

<Note>
  This is the containerized path. If you'd rather install `geniex` directly on the host without Docker, see [CLI Install → Linux ARM64 (Native)](/en/run/cli/install).
</Note>

### **Prerequisites**

- Linux ARM64 host with Docker installed — if you don't have Docker yet, follow [Docker's Ubuntu install guide](https://docs.docker.com/engine/install/ubuntu/).
- Dragonwing IoT chipset — see [Supported platforms](/en/get-started/platforms).

### **Install host dependencies**

The container reaches the NPU through the host's Qualcomm driver libraries, mounted in via `-v /usr/lib:/opt/qcom-lib:ro`. Install them **on the host** before `docker run` — follow [CLI Install → Install host dependencies](/en/run/cli/install#install-host-dependencies).

### **Pull the image**

The image is on Docker Hub (public, no login):

```bash bash
IMAGE=docker.io/qualcomm/geniex:latest

docker pull "$IMAGE"
```

<Note>
  If `docker pull` returns `permission denied ... /var/run/docker.sock`, see [Troubleshooting → Linux](/en/resources/troubleshooting#linux) for the `docker` group fix.
</Note>

<Note>
  **Baseline ARMv8.0 boards** — some NPU-less Dragonwing IoT SoCs cannot run the default ARMv8.2 image; append `-cpu` to the tag for those: `docker.io/qualcomm/geniex:latest-cpu`. That image is CPU-only and needs neither `--privileged` nor the `/usr/lib` mount below.
</Note>

### **Run interactively**

Drop into an interactive shell inside the container:

```bash bash
docker run -it --rm --privileged \
  -v "$PWD/data:/data" \
  -v /usr/lib:/opt/qcom-lib:ro \
  "$IMAGE"
```

### **Verify**

Then run a test command from the container shell:

```bash bash
geniex --help
```

<Note>The `--privileged` flag is required for NPU access.</Note>

For server mode, see [Local server](/en/run/cli/local-server).

## **Non-Snapdragon arm64 hosts**

To try the GenieX CLI on an arm64 machine without a Snapdragon chipset, such as an Apple Silicon Mac running Docker Desktop, build the CPU-only image from [`.github/docker/cpu-host.Dockerfile`](https://github.com/qualcomm/GenieX/blob/main/.github/docker/cpu-host.Dockerfile). It wraps `docker.io/qualcomm/geniex:latest-cpu`, needs neither `--privileged` nor the `/usr/lib` mount, sets a chipset on first start so `geniex pull` doesn't prompt for one, and makes `geniex infer` default to `--compute cpu`.

<Warning>
  This path is for development and testing. It runs on CPU only, so its speed doesn't reflect Snapdragon performance. Use GGUF models on the `llama_cpp` runtime: Qualcomm AI Hub bundles need the NPU.
</Warning>

The image isn't published to Docker Hub, so build it from a clone of this repository:

```bash bash
git clone --depth 1 https://github.com/qualcomm/GenieX.git
cd GenieX
docker build -f .github/docker/cpu-host.Dockerfile -t geniex-cpu-host .
```

Start a container, keeping models in `./data`:

```bash bash
docker run -it --rm -v "$PWD/data:/data" geniex-cpu-host
```

Then pull a model and run it from the container shell:

```bash bash
geniex pull unsloth/Qwen3-VL-2B-Instruct-GGUF:Q4_0 --model-type vlm
geniex infer unsloth/Qwen3-VL-2B-Instruct-GGUF:Q4_0 -p "Describe this image: /data/image.jpg"
```

Image paths must be absolute paths inside the container, so put images in `./data` on the host.

<Note>
  Tested on an Apple M1 Max with Docker Desktop and GenieX CLI v0.10.0. Set `GENIEX_CHIPSET` to start with a different chipset. An existing chipset in `/data` is left unchanged.
</Note>
